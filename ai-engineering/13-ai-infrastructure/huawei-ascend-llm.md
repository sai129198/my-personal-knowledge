# 华为昇腾在 LLM 领域的角色与现状

> 研究时间: 2026-07-27
> 标签: #status/canonical #topic/ai-infrastructure #topic/llm #topic/chip #year/2026
> 起因: 讨论 GLM-5.2 与 DeepSeek V4 是否使用华为昇腾训练，深入梳理国产 NPU 在大模型生态中的真实定位。

---

## 一句话总结

**华为昇腾现阶段的核心价值是让国内 LLM 的"落地"（推理、微调、部署）不依赖英伟达，但在千亿级预训练和前沿探索训练上仍无法替代 NVIDIA CUDA 生态。**

---

## 昇腾在 LLM 各阶段的成熟度

```
🏆 推理服务        ← 最成熟，已经大规模商用
🏆 信创市场        ← 政策护城河，别无选择
🥈 后训练/微调     ← 能做，成本可接受
🥉 小规模预训练    ← 能做但费劲
🤔 千亿级预训练    ← 理论上能，实际上极少团队敢赌
❌ 前沿探索训练    ← 目前不现实
```

---

## 1. 已经落地、确定性高的事

### 1.1 推理部署（最主要战场）

国内大量模型的线上推理服务已经跑在昇腾上：

| 模型方 | 昇腾使用情况 |
|--------|:----------|
| 智谱 GLM 系列 | 推理服务已适配，部分线上流量走昇腾集群 |
| 讯飞星火 | 与华为深度合作，推理大规模部署在昇腾上 |
| 百度文心一言 | 部分推理负载在昇腾上 |
| 各地方政府政务大模型 | 信创要求，几乎只能选昇腾 |

**为什么推理能跑？** 推理对集群稳定性、通信效率的要求远低于预训练，单卡就能干活。昇腾 910B/910C 的推理性能（尤其量化后）已经可接受。

### 1.2 微调 / LoRA / 后训练

单机或小规模集群上的微调任务，昇腾可以胜任：

- **全参微调 7B-13B 模型**：单机 8 卡昇腾 910B 完全够用
- **LoRA 微调 70B 模型**：可以在昇腾集群上完成
- **部分 RLHF / DPO 阶段**：不需要千卡级集群，昇腾也能做

### 1.3 信创 / 党政军市场

这是昇腾的"护城河"市场：

- 政务大模型、军工 AI → 必须国产化，只有昇腾可选
- 运营商（移动/电信/联通）的大模型项目 → 同样有国产化要求
- 这些场景不需要训千亿模型，主要是部署和微调

---

## 2. 在起步、但还差火候的事

### 2.1 千亿级模型预训练

- **910B**（2023-2024 主力）：单卡算力约 A100 的 80%，但集群稳定性、互联带宽、软件生态差距大
- **910C**（2024-2025）：算力提升，但大规模集群（千卡以上）的稳定训练仍是挑战
- 华为自己用昇腾训练了盘古大模型，证明"能训"，但效率、成本、稳定性跟 NVIDIA 集群还有差距

### 2.2 关键瓶颈：不在单卡算力，在软件生态

| 维度 | NVIDIA | 华为昇腾 |
|------|:------:|:------:|
| 算子覆盖度 | 极全（cuBLAS, cuDNN, cuSPARSE...） | CANN 仍在追赶 |
| 调试工具链 | Nsight, cuda-gdb 成熟 | 相对简陋 |
| 框架适配 | PyTorch/JAX/TF 开箱即用 | 需要 torch_npu 插件，存在算子缺失 |
| 社区生态 | 全球开发者，无数开源项目 | 国内为主，生态小 |
| 第三方支持 | vLLM, SGLang, llama.cpp 默认 CUDA | 需额外适配 |

---

## 3. 目前基本不做的事

### 3.1 海外 / 开源模型的先锋训练

DeepSeek、Qwen、Llama 之类的前沿探索性预训练，几乎不可能用昇腾：

- 这些团队追求极致效率，CUDA 生态优化到骨头里
- 迁移成本极高，且迁移后可能反而变慢
- 开源社区的复现、二次训练也都是 CUDA 生态

---

## 4. DeepSeek V4 与 GLM-5 的实际情况

| 模型 | 预训练主力芯片 | 是否用华为昇腾 |
|------|:----------:|:----------:|
| DeepSeek V4/V4 Pro | NVIDIA H800/H100 | ❌ 无公开证据 |
| GLM-5/5.2 | NVIDIA（为主）+ 部分昇腾 | ✅ 有适配，部分阶段使用 |

- **DeepSeek**：核心优势是极致的 CUDA 训练效率优化（MoE 架构、FP8 混合精度、通信优化等），深度绑定 NVIDIA 生态，迁移到 CANN 成本不可接受
- **智谱**：与华为有深度合作，模型推理已在昇腾大规模部署，部分后训练任务可能使用昇腾，但千亿级预训练主力仍是 NVIDIA

---

## 5. 生态对照

| NVIDIA 生态 | 华为昇腾生态 | 角色 |
|:--|:--|:--|
| CUDA + cuDNN | CANN（昇腾计算架构） | GPU/NPU 的"操作系统" |
| PyTorch (CUDA 后端) | PyTorch (昇腾 backend) + 昇思 MindSpore | 上层框架 |

昇腾的挑战不在于芯片算力不够，而在于 CANN 的成熟度远不如 CUDA——算子不够全、调试工具不好用、社区生态小。要让 PyTorch 适配昇腾，需要把大量 CUDA 算子逐一翻译成 CANN 版本，这是巨大的工程。
