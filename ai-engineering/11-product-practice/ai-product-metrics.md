# AI 产品指标与评估

> **一句话定位**：AI 产品的成功需要科学的指标体系——从技术指标到业务指标，全面衡量 AI 产品价值。

---

## 1. AI 产品指标体系框架

### 1.1 三层指标体系

```
┌─────────────────────────────────────────┐
│  业务层指标 (Business Metrics)           │
│  - 收入、用户增长、市场份额               │
├─────────────────────────────────────────┤
│  产品层指标 (Product Metrics)            │
│  - 用户活跃度、留存、满意度               │
├─────────────────────────────────────────┤
│  技术层指标 (Technical Metrics)          │
│  - 模型性能、系统性能、成本               │
└─────────────────────────────────────────┘
```

### 1.2 指标选择原则

**SMART 原则**：
- **S**pecific：指标定义清晰
- **M**easurable：可量化测量
- **A**chievable：目标可实现
- **R**elevant：与业务目标相关
- **T**ime-bound：有明确时间范围

## 2. 技术层指标

### 2.1 模型性能指标

#### 2.1.1 分类任务

| 指标 | 公式 | 适用场景 |
|------|------|----------|
| **准确率 (Accuracy)** | (TP+TN)/(TP+TN+FP+FN) | 类别平衡的数据集 |
| **精确率 (Precision)** | TP/(TP+FP) | 关注误报成本 |
| **召回率 (Recall)** | TP/(TP+FN) | 关注漏报成本 |
| **F1 Score** | 2×Precision×Recall/(Precision+Recall) | 综合评估 |
| **AUC-ROC** | ROC 曲线下面积 | 评估模型区分能力 |

#### 2.1.2 生成任务

| 指标 | 说明 | 适用场景 |
|------|------|----------|
| **BLEU** | n-gram 精确度 | 机器翻译、文本生成 |
| **ROUGE** | 召回导向的 n-gram 重叠 | 摘要生成 |
| **METEOR** | 考虑同义词和词干 | 机器翻译 |
| **CIDEr** | 基于 TF-IDF 的 n-gram | 图像描述 |
| **SPICE** | 基于语义命题 | 图像描述 |

#### 2.1.3 检索任务

| 指标 | 公式 | 说明 |
|------|------|------|
| **Precision@K** | 前 K 个结果中相关比例 | 关注顶部结果质量 |
| **Recall@K** | 前 K 个结果覆盖相关文档比例 | 关注覆盖率 |
| **NDCG@K** | 归一化折损累积增益 | 考虑排序位置 |
| **MRR** | 平均倒数排名 | 关注首个相关结果位置 |
| **MAP** | 平均精度均值 | 综合评估检索质量 |

### 2.2 系统性能指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| **延迟 (Latency)** | 请求响应时间 | P99 < 200ms |
| **吞吐量 (Throughput)** | 每秒处理请求数 | > 1000 QPS |
| **可用性 (Availability)** | 系统正常运行时间 | > 99.9% |
| **错误率 (Error Rate)** | 请求失败比例 | < 0.1% |
| **资源利用率** | CPU/GPU/内存使用 | 70-80% |

### 2.3 成本指标

| 指标 | 说明 | 优化方向 |
|------|------|----------|
| **推理成本** | 每次推理的计算成本 | 模型量化、蒸馏 |
| **存储成本** | 模型和数据存储成本 | 模型压缩、数据清理 |
| **训练成本** | 模型训练的计算成本 | 高效训练、迁移学习 |
| **人力成本** | 标注和运维人力 | 自动化、工具化 |

## 3. 产品层指标

### 3.1 用户活跃度指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **DAU/MAU** | 日活/月活用户 | 去重用户数 |
| **功能使用率** | AI 功能使用比例 | 使用功能用户数/总用户数 |
| **使用频次** | 人均使用次数 | 总使用次数/用户数 |
| **使用时长** | 人均使用时长 | 总时长/用户数 |

### 3.2 用户留存指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **次日留存** | 次日仍使用的用户比例 | 次日活跃用户/首日用户 |
| **7 日留存** | 7 日后仍使用的用户比例 | 7 日活跃用户/首日用户 |
| **30 日留存** | 30 日后仍使用的用户比例 | 30 日活跃用户/首日用户 |
| **流失率** | 停止使用的用户比例 | 流失用户/总用户 |

### 3.3 用户满意度指标

| 指标 | 说明 | 测量方式 |
|------|------|----------|
| **NPS** | 净推荐值 | "您有多大可能推荐？" 0-10 分 |
| **CSAT** | 客户满意度 | "您对服务满意吗？" 1-5 分 |
| **CES** | 客户费力度 | "解决问题花费了多少 effort？" |
| **用户反馈** | 定性反馈 | 用户评论、反馈表单 |

### 3.4 任务完成指标

| 指标 | 说明 | 测量方式 |
|------|------|----------|
| **任务完成率** | 成功完成任务的比例 | 成功次数/总尝试次数 |
| **任务完成时间** | 完成任务所需时间 | 从开始到成功的时间 |
| **错误恢复率** | 从错误中恢复的比例 | 恢复成功次数/错误次数 |
| **用户求助率** | 需要人工帮助的比例 | 求助次数/总任务数 |

## 4. 业务层指标

### 4.1 收入指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **ARPU** | 每用户平均收入 | 总收入/用户数 |
| **LTV** | 用户生命周期价值 | 用户在整个生命周期的总价值 |
| **CAC** | 用户获取成本 | 总营销成本/新用户数 |
| **LTV/CAC** | 价值获取比 | 应 > 3:1 |
| **MRR/ARR** | 月度/年度经常性收入 | 订阅收入 |

### 4.2 增长指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **用户增长率** | 用户增长比例 | (本期用户-上期用户)/上期用户 |
| **病毒系数** | 每个用户带来新用户数 | 邀请成功数/总用户数 |
| **转化率** | 从免费到付费的转化 | 付费用户数/总用户数 |
| **市场份额** | 在目标市场的占比 | 产品用户/市场总用户 |

## 5. AI 特有指标

### 5.1 模型可信度指标

| 指标 | 说明 | 测量方式 |
|------|------|----------|
| **置信度分布** | 模型预测的置信度分布 | 统计预测概率 |
| **校准度** | 预测概率与实际准确率的一致性 | 可靠性图、ECE |
| **不确定性** | 模型对预测的不确定性 | 熵、MC Dropout |
| **OOD 检测** | 检测分布外样本的能力 | AUROC |

### 5.2 公平性指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **人口统计均等** | 不同群体的正例率相等 | P(Ŷ=1\|A=0) = P(Ŷ=1\|A=1) |
| **机会均等** | 不同群体的真正例率相等 | P(Ŷ=1\|Y=1,A=0) = P(Ŷ=1\|Y=1,A=1) |
| **预测均等** | 不同群体的精确率相等 | P(Y=1\|Ŷ=1,A=0) = P(Y=1\|Ŷ=1,A=1) |

### 5.3 可解释性指标

| 指标 | 说明 | 测量方式 |
|------|------|----------|
| **特征重要性** | 各特征对预测的贡献 | SHAP、LIME |
| **决策路径** | 模型的决策逻辑 | 决策树可视化 |
| **反事实解释** | 如何改变输入以改变输出 | 反事实生成 |

## 6. 指标监控与告警

### 6.1 监控体系

```
┌─────────────────────────────────────────┐
│           数据收集层                     │
│  - 日志、指标、追踪                      │
├─────────────────────────────────────────┤
│           数据处理层                     │
│  - 聚合、计算、存储                      │
├─────────────────────────────────────────┤
│           可视化层                       │
│  - 仪表盘、报表                          │
├─────────────────────────────────────────┤
│           告警层                         │
│  - 阈值、异常检测                        │
└─────────────────────────────────────────┘
```

### 6.2 告警策略

| 级别 | 条件 | 响应时间 |
|------|------|----------|
| **P0 (Critical)** | 系统不可用、核心功能故障 | 立即 |
| **P1 (High)** | 性能严重下降、大量错误 | 15 分钟 |
| **P2 (Medium)** | 性能下降、少量错误 | 1 小时 |
| **P3 (Low)** | 非核心功能问题 | 1 天 |

### 6.3 监控工具

| 工具 | 用途 | 特点 |
|------|------|------|
| **Prometheus** | 指标收集 | 时序数据库、强大的查询语言 |
| **Grafana** | 可视化 | 丰富的图表和仪表盘 |
| **ELK Stack** | 日志分析 | 全文搜索、实时分析 |
| **Jaeger** | 分布式追踪 | 请求链路追踪 |
| **Datadog** | 综合监控 | SaaS 方案、易于集成 |

## 7. 评估方法论

### 7.1 离线评估

**适用场景**：模型上线前的评估

**方法**：
- **交叉验证**：K-fold 交叉验证
- **时间划分**：按时间顺序划分训练/测试集
- **A/B 测试**：离线模拟 A/B 测试

**注意事项**：
- 数据泄露：确保测试集不会泄露到训练集
- 分布偏移：评估数据应与实际数据分布一致
- 样本量：确保统计显著性

### 7.2 在线评估

**适用场景**：模型上线后的持续评估

**方法**：
- **A/B 测试**：对照组 vs 实验组
- **影子测试**：新模型与旧模型并行运行
- **金丝雀发布**：小流量验证

**关键指标**：
- 业务指标：收入、转化率、留存
- 用户指标：满意度、使用时长
- 技术指标：延迟、错误率

### 7.3 人工评估

**适用场景**：无法自动评估的场景

**方法**：
- **专家评估**：领域专家人工评分
- **众包评估**：通过众包平台收集评估
- **用户反馈**：收集用户直接反馈

**评估维度**：
- 准确性：输出是否正确
- 相关性：输出是否与输入相关
- 流畅性：输出是否自然流畅
- 安全性：输出是否安全无害

## 8. 指标驱动的产品优化

### 8.1 优化循环

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  定义指标  │ -> │  收集数据  │ -> │  分析洞察  │ -> │  优化产品  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
      ↑                                              │
      └──────────────────────────────────────────────┘
```

### 8.2 常见优化策略

| 问题 | 可能原因 | 优化策略 |
|------|----------|----------|
| 准确率低 | 模型能力不足 | 模型升级、数据增强 |
| 延迟高 | 模型复杂 | 模型量化、蒸馏、缓存 |
| 用户留存低 | 产品体验差 | 优化交互、增加功能 |
| 转化率低 | 价值不清晰 | 优化价值主张、降低门槛 |
| 成本高 | 资源消耗大 | 模型优化、架构调整 |

---

## 9. 总结

AI 产品评估需要**多维度、多层级**的指标体系：

1. **技术指标**：衡量模型和系统性能
2. **产品指标**：衡量用户体验和产品健康度
3. **业务指标**：衡量商业价值和增长

**关键原则**：
- 指标应与业务目标对齐
- 建立完整的监控和告警体系
- 持续优化，数据驱动决策

> **关键洞察**：好的 AI 产品不仅需要优秀的模型，还需要科学的评估体系和持续优化的机制。指标是连接技术和业务的桥梁。
