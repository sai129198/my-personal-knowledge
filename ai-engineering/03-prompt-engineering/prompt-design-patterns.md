# Prompt 设计模式大全

> 系统梳理与大模型交互的核心模式，从简单到复杂，从单轮到多轮。

---

## 1. 基础模式

### 1.1 Zero-Shot Prompting（零样本提示）

**定义**：直接给出指令，不提供示例。

```
将以下中文翻译成英文：
"人工智能正在改变我们的生活方式。"
```

**适用场景**：
- 模型已具备该任务能力
- 任务定义清晰明确
- 追求简洁和效率

**局限性**：
- 对复杂或模糊任务效果不佳
- 输出格式难以控制
- 容易产生幻觉

---

### 1.2 Few-Shot Prompting（少样本提示）

**定义**：提供几个输入-输出示例，让模型学习模式。

```
将情感分类为正面、负面或中性。

示例 1：
文本：这部电影太精彩了！
情感：正面

示例 2：
文本：排队等了一个小时，体验很差。
情感：负面

示例 3：
文本：今天天气晴朗。
情感：中性

现在分类：
文本：这家餐厅的服务态度非常好，菜品也很新鲜。
情感：
```

**关键要点**：
- 示例质量 > 数量（通常 1-5 个足够）
- 示例应覆盖边缘情况
- 示例格式与期望输出完全一致
- 示例顺序可能影响结果（recency bias）

**变体：K-shot 选择策略**

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 随机采样 | 从训练集随机选 K 个 | 数据分布均匀 |
| 相似度检索 | 选与输入最相似的 K 个 | 任务多样 |
| 多样性采样 | 选覆盖不同类别的 K 个 | 类别不平衡 |
| 动态 K | 根据输入复杂度调整 K | 资源受限 |

---

### 1.3 Role Prompting（角色提示）

**定义**：让模型扮演特定角色，激活相关知识和行为模式。

```
你是一位资深 Java 架构师，拥有 15 年分布式系统开发经验。
请review以下代码，关注：
1. 线程安全性
2. 性能瓶颈
3. 设计模式应用
4. 可维护性

代码：
[...]
```

**有效角色类型**：
- **专业角色**：医生、律师、工程师、教授
- **风格角色**：诗人、小说家、技术写手
- **功能角色**：代码审查员、面试官、辩论对手
- **认知角色**：批判性思考者、创意发散者、细节检查员

**进阶技巧**：多重角色组合

```
请你分别扮演以下三个角色，对同一个方案给出评估：

1. 【安全架构师】：关注安全漏洞和合规风险
2. 【性能工程师】：关注高并发和响应时间
3. 【产品经理】：关注用户体验和商业价值

方案：...
```

## 2. 推理增强模式

### 2.1 Chain-of-Thought (CoT) 思维链

**定义**：引导模型逐步推理，而非直接给出答案。

**手动 CoT**：
```
问题：一个农场有鸡和兔共 35 只，脚共 94 只。鸡和兔各有多少只？

请按以下步骤思考：
1. 设鸡有 x 只，兔有 y 只
2. 根据题意列出方程
3. 解方程
4. 验证答案

思考过程：
```

**自动 CoT（Zero-shot-CoT）**：
```
问题：一个农场有鸡和兔共 35 只，脚共 94 只。鸡和兔各有多少只？

让我们一步步思考：
```

只需添加 "Let's think step by step" 或 "让我们一步步思考"，即可激活模型的推理能力。

**CoT 有效性原理**：
- 强制模型生成中间步骤，减少跳步错误
- 增加计算 budget（更多 token → 更多思考）
- 中间步骤可验证、可调试

**适用任务类型**：
- ✅ 数学推理
- ✅ 逻辑谜题
- ✅ 多步骤计算
- ✅ 因果推理
- ❌ 简单事实查询（增加不必要的开销）
- ❌ 创意生成（可能限制发散性）

---

### 2.2 Tree of Thoughts (ToT) 思维树

**定义**：维护多个推理路径，通过评估选择最优路径。

```
问题：24 点游戏，用 4、5、6、8 算出 24。

思考过程：

路径 A：尝试乘法为主
- 4 × 6 = 24，还需要用 5 和 8 得到 1（×1 或 +0）
  - 8 - 5 = 3 ≠ 1 ❌
  - 5 / 8 = 0.625 ≠ 1 ❌
- 放弃路径 A

路径 B：尝试 (a + b) × c 模式
- (5 - 4) × 8 = 8，8 + 6 = 14 ≠ 24 ❌
- (6 - 5) × 8 = 8，8 × 4 = 32 ≠ 24 ❌
- (8 - 5) × 4 = 12，12 + 6 = 18 ≠ 24 ❌
- (8 - 6) × 5 = 10，10 × 4 = 40 ≠ 24 ❌
- (6 - 4) × 5 = 10，10 + 8 = 18 ≠ 24 ❌
- 放弃路径 B

路径 C：尝试 a × b + c × d 模式
- 4 × 5 = 20，6 + 8 = 14，20 + 14 = 34 ≠ 24 ❌
- 4 × 6 = 24，5 + 8 = 13，24 + 13 = 37 ≠ 24 ❌
- 4 × 8 = 32，5 + 6 = 11，32 - 11 = 21 ≠ 24 ❌
- 5 × 6 = 30，4 + 8 = 12，30 - 12 = 18 ≠ 24 ❌
- 6 × 8 = 48，4 + 5 = 9，48 / ... 不太对
- 放弃路径 C

路径 D：尝试更复杂的组合
- 8 / (5 - 4) = 8，8 × 6 = 48，48 / ... 
- (6 - 4 / 5) × ... 不太整
- 4 × (8 - 6 + 5) = 4 × 7 = 28 ≠ 24 ❌
- 6 / (1 - 5/8) ... 需要 1 - 5/8 = 3/8，6 / (3/8) = 16 ≠ 24
- 8 / (3 - 5/6) ... 3 - 5/6 = 13/6，8 / (13/6) 不整
- (5 + 3) × ... 没有 3
- 4! = 24，需要用 5、6、8 得到 0（+0 或 ×1）
  - 6 + 5 - 8 = 3 ≠ 0 ❌
  - 8 - 6 + 5 = 7 ≠ 0 ❌
  - 8 / (6 - 5) = 8 ≠ 1 ❌
  - (8 - 6) / 5 = 0.4 ≠ 0 ❌
- 放弃路径 D

路径 E：尝试除法创造有用分数
- 8 / 4 = 2，然后 2 × 6 + 5 = 17 ≠ 24
- 8 / 4 = 2，然后 2 + 6 × 5 = 32 ≠ 24
- 6 / (something) ...
- 5 - 4 = 1，然后 1 + 6 + 8 = 15，不对
- 重新思考：4 / (1 - 5/6) ... 1 - 5/6 = 1/6，4 / (1/6) = 24！但这样用了 4、5、6，还剩下 8
- 需要把 8 也用上且结果为 1（×1）或 0（+0）
  - 8/8 = 1，但只有一个 8
  - 8 - 8 = 0，但只有一个 8
- 重新组织：4 / (1 - 5/6) × (8/8) ... 不行

路径 F：重新出发
- 6 / (1 - 3/4) = 24，需要 3 和 1，有 5 和 8
  - 8 - 5 = 3 ✓
  - 但 1 从哪里来？
  - 实际上：6 / (1 - (8-5)/4) = 6 / (1 - 3/4) = 6 / (1/4) = 24 ✓
  - 验证：6 / (1 - (8-5)/4) = 6 / (1 - 3/4) = 6 / (1/4) = 24 ✓✓✓

答案：6 / (1 - (8 - 5) / 4) = 24
```

**ToT 核心机制**：
1. **分解**：将问题分解为多个思考步骤
2. **生成**：每个步骤生成多个候选想法
3. **评估**：评估每个候选的 promising 程度
4. **搜索**：选择最有希望的继续展开（BFS/DFS）
5. **回溯**：遇到死胡同返回重新探索

**适用场景**：
- 需要探索的开放性问题
- 游戏和谜题（24点、数独、 chess）
- 创意写作（多情节分支）
- 复杂决策（多方案对比）

### 2.3 Self-Consistency（自我一致性）

**定义**：多次采样生成多个 CoT 推理路径，投票选出最一致的答案。

```python
# 伪代码
answers = []
for i in range(10):  # 生成 10 个推理路径
    response = model.generate(prompt, temperature=0.7)
    answer = extract_answer(response)
    answers.append(answer)

final_answer = most_common(answers)  # 投票
```

**为什么有效**：
- 单次 CoT 可能产生推理错误
- 多次独立采样降低随机错误概率
- 正确答案往往在多数路径中收敛

**成本权衡**：
- 10 次采样 ≈ 10× 成本
- 可在准确率和成本之间调整采样次数
- 对关键任务（医疗、金融）值得投入

## 3. 工具使用模式

### 3.1 ReAct (Reasoning + Acting)

**定义**：交替进行推理（Thought）和行动（Action），让模型与外部工具交互。

```
你需要回答用户问题，可以使用以下工具：
- search(query): 搜索引擎
- calculator(expression): 计算器
- weather(city): 天气查询

格式要求：
Thought: [你的思考过程]
Action: [工具名称]([参数])
Observation: [工具返回结果]
...（重复 Thought-Action-Observation）
Final Answer: [最终答案]

---

问题：2024 年诺贝尔奖物理学奖得主是谁？他/她现在的年龄是多少？

Thought: 我需要先搜索 2024 年诺贝尔物理学奖得主的信息。
Action: search("2024 Nobel Prize Physics winner")
Observation: 2024 年诺贝尔物理学奖授予 John J. Hopfield 和 Geoffrey E. Hinton，以表彰他们在人工神经网络和机器学习方面的基础性发现和发明。

Thought: 现在我需要分别查询两位得主的出生年份，然后计算年龄。
Action: search("John J. Hopfield birth year")
Observation: John J. Hopfield 出生于 1933 年 7 月 15 日。

Thought: 计算 John Hopfield 的年龄：2024 - 1933 = 91 岁。
Action: calculator("2024 - 1933")
Observation: 91

Thought: 现在查询 Geoffrey Hinton 的信息。
Action: search("Geoffrey E. Hinton birth year")
Observation: Geoffrey Everest Hinton 出生于 1947 年 12 月 6 日。

Thought: 计算 Geoffrey Hinton 的年龄：2024 - 1947 = 77 岁。
Action: calculator("2024 - 1947")
Observation: 77

Thought: 我已经获得了所有需要的信息，可以给出最终答案。
Final Answer: 2024 年诺贝尔物理学奖授予 John J. Hopfield（91 岁）和 Geoffrey E. Hinton（77 岁），以表彰他们在人工神经网络和机器学习方面的基础性贡献。
```

**ReAct 优势**：
- 推理过程透明可追溯
- 减少幻觉（事实通过工具验证）
- 可处理实时信息
- 错误可定位到具体步骤

**现代实现**：
- OpenAI Function Calling
- Anthropic Tool Use
- LangChain Agent
- AutoGPT

### 3.2 Plan-and-Solve（规划与求解）

**定义**：先制定计划，再按步骤执行。

```
问题：计算一家电商公司 Q3 的毛利率变化。

计划：
1. 获取 Q3 和 Q2 的营收数据
2. 获取 Q3 和 Q2 的销售成本
3. 计算各季度毛利率 = (营收 - 成本) / 营收
4. 计算毛利率变化百分比
5. 分析变化原因

执行：
Step 1: [调用数据 API 获取营收]
Step 2: [调用数据 API 获取成本]
Step 3: [计算]
...
```

**与 ReAct 区别**：
- Plan-and-Solve：先完整规划，再执行
- ReAct：边思考边行动，动态调整

**适用场景**：
- 任务步骤明确且可预见
- 需要资源协调（如并行调用多个 API）
- 复杂报告生成

## 4. 多智能体模式

### 4.1 Multi-Agent Debate（多智能体辩论）

**定义**：多个模型实例扮演不同角色，通过辩论达成共识。

```
主题：是否应该在公司全面推行 AI 编程助手？

【正方 Agent - 技术总监】
观点：应该全面推行
论据：1. 提升开发效率 30-50%
      2. 减少重复性工作
      3. 降低初级错误率
      ...

【反方 Agent - 安全主管】
观点：应该谨慎推行
论据：1. 代码安全风险
      2. 知识产权问题
      3. 过度依赖导致能力退化
      ...

【裁判 Agent - CEO】
综合双方观点，考虑：
- 业务紧迫性
- 风险承受能力
- 实施成本

最终决策：...
```

**实现方式**：
- 同一模型的不同 system prompt
- 不同模型（GPT-4 vs Claude）
- 专门的辩论框架（如 ChatEval）

---

### 4.2 Reflection（反思模式）

**定义**：模型生成初稿后，自我批评并改进。

```
【生成阶段】
请写一篇关于"AI 安全"的技术博客。

[生成初稿]

【反思阶段】
请从以下角度 critique 上述文章：
1. 技术准确性
2. 逻辑连贯性
3. 受众适配度
4. 遗漏的重要观点

[生成 critique]

【改进阶段】
请根据上述 critique 改进文章。

[生成终稿]
```

**变体：Reflexion**
- 引入外部评估（如单元测试、人工反馈）
- 将失败经验存储到记忆中
- 下次遇到类似任务时自动改进

## 5. 高级技巧

### 5.1 Prompt Chaining（提示链）

**定义**：将复杂任务分解为多个子任务，串联执行。

```
任务：从用户评论中提取洞察并生成报告

Step 1 - 提取：
"从以下评论中提取所有提到的产品问题和功能建议：
[评论列表]"
→ 输出：结构化问题列表

Step 2 - 分类：
"将以下问题按类型分类（Bug/性能/UX/功能请求）：
[Step 1 输出]"
→ 输出：分类后的问题

Step 3 - 优先级：
"根据影响范围和频率，为以下问题排序：
[Step 2 输出]"
→ 输出：优先级列表

Step 4 - 报告：
"基于以下优先级列表，生成一份产品改进建议报告：
[Step 3 输出]"
→ 输出：最终报告
```

**优势**：
- 每个步骤可控可调试
- 中间结果可复用
- 错误不会级联放大
- 可并行化独立步骤

---

### 5.2 Directional Stimulus Prompting（定向刺激）

**定义**：在 prompt 中加入引导性提示，控制模型注意力。

```
【标准 Prompt】
总结以下文章：
[长文章]

【定向刺激 Prompt】
总结以下文章，特别关注：
- 作者的核心论点
- 使用的关键证据
- 对 [具体领域] 的启示
- 潜在的局限性

[长文章]
```

**变体：Emotion Prompting**
```
这对我的职业生涯非常重要，请确保你的回答准确且全面。
```
研究表明，加入情感暗示可提升模型表现（尤其在需要细致处理的任务上）。

---

### 5.3 Generated Knowledge Prompting（生成知识提示）

**定义**：先让模型生成相关知识，再基于知识回答问题。

```
Step 1 - 生成知识：
"生成 5 条关于'量子计算对密码学影响'的关键事实："
→ [知识列表]

Step 2 - 基于知识回答：
"基于以下事实，回答：量子计算会完全破解现有加密体系吗？
[知识列表]"
→ [最终答案]
```

**为什么有效**：
- 显式提取模型内部知识
- 减少知识检索错误
- 答案基于显式事实而非隐式记忆

## 6. 模式选择决策树

```
任务分析
    │
    ├─ 需要事实查询/实时信息？
    │   ├─ 是 → ReAct / Tool Use
    │   └─ 否 → 继续
    │
    ├─ 需要多步推理？
    │   ├─ 是 → 继续
    │   └─ 否 → Zero-Shot / Few-Shot
    │
    ├─ 推理路径不确定？
    │   ├─ 是 → Tree of Thoughts
    │   └─ 否 → Chain-of-Thought
    │
    ├─ 答案可验证？
    │   ├─ 是 → Self-Consistency（多次采样投票）
    │   └─ 否 → 单次 CoT
    │
    ├─ 任务可分解？
    │   ├─ 是 → Prompt Chaining
    │   └─ 否 → 继续
    │
    ├─ 需要多角度思考？
    │   ├─ 是 → Multi-Agent Debate
    │   └─ 否 → 继续
    │
    └─ 需要高质量输出？
        ├─ 是 → Reflection（生成-反思-改进）
        └─ 否 → 基础模式
```

## 💡 我的思考

1. **Prompt 工程的本质是「沟通艺术」**：不是让模型变聪明，而是让模型「正确理解」你的意图。清晰的指令、恰当的示例、合理的约束，比复杂的技巧更重要。

2. **模式可以组合**：实际应用中很少只用一种模式。例如：ReAct + CoT + Self-Consistency 可以同时使用，获得更好的效果。

3. **成本意识**：复杂模式（ToT、Multi-Agent）带来准确率提升的同时，也带来成本增加。需要在效果和成本之间找到平衡点。

4. **Prompt 是「软件」**：应该像管理代码一样管理 prompt——版本控制、A/B 测试、性能监控、文档化。

5. **模型能力在进化**：GPT-4 时代的最佳实践可能不适用于 GPT-5。保持对模型能力边界的持续认知更新。

6. **少即是多**：很多时候，一个清晰的 Zero-Shot prompt 比堆砌技巧的复杂 prompt 效果更好。先从简单开始，必要时再增加复杂度。
