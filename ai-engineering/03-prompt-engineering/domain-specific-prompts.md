# 领域专用 Prompt 模板

> 针对代码、写作、数据分析、创意生成等场景的即用型 Prompt 模板。

---

## 1. 代码开发

### 1.1 代码审查

```
你是一位资深 {语言} 开发工程师，请审查以下代码。

审查维度：
1. 🐛 Bug 风险
2. ⚡ 性能问题
3. 🔒 安全隐患
4. 📖 可读性
5. 🧪 可测试性
6. 📐 设计模式

代码：
```{语言}
{代码}
```

请按以下格式输出：

## 严重问题（必须修复）
- [行号] [问题描述] [修复建议]

## 改进建议（建议采纳）
- [行号] [问题描述] [改进方案]

## 正面评价
- [做得好的地方]

## 总体评分
- 代码质量：x/10
- 安全性：x/10
- 可维护性：x/10
```

### 1.2 代码生成

```
请实现一个 {功能描述}。

要求：
- 语言：{语言}
- 输入：{输入格式}
- 输出：{输出格式}
- 约束：{时间/空间复杂度要求}
- 边界情况：{需要处理的特殊情况}

请提供：
1. 实现代码（含注释）
2. 复杂度分析
3. 单元测试（覆盖边界情况）
```

### 1.3 代码解释

```
请解释以下代码的工作原理。

要求：
- 用通俗易懂的语言解释
- 逐行/逐块分析关键逻辑
- 说明设计意图和权衡
- 指出潜在问题（如有）

代码：
```
{代码}
```

请按以下结构输出：
1. 整体功能概述（1-2 句话）
2. 关键逻辑详解
3. 数据流分析
4. 设计模式/算法识别
5. 潜在改进点
```

## 2. 技术写作

### 2.1 技术博客

```
请撰写一篇关于 {主题} 的技术博客。

目标受众：{初级/中级/高级} {开发者/产品经理/管理者}
字数：{字数} 字
风格：{教程型/观点型/案例分析型}

结构要求：
1. 引人入胜的开头（问题或场景）
2. 核心概念解释（用类比）
3. 实践示例（含代码/截图）
4. 常见陷阱和解决方案
5. 总结和下一步

特殊要求：
- 包含至少 1 个类比解释
- 包含至少 1 个实际案例
- 使用表格对比不同方案
- 结尾给出可操作的 checklist
```

### 2.2 文档生成

```
请为以下 API/函数生成技术文档。

格式：{OpenAPI/Markdown/Javadoc}
深度：{简要/详细/完整}

代码：
```
{代码}
```

文档应包含：
- 功能描述
- 参数说明（名称、类型、必填、默认值、说明）
- 返回值说明
- 异常说明
- 使用示例（至少 2 个）
- 相关链接
```

## 3. 数据分析

### 3.1 数据探索

```
我有一份 {数据类型} 数据，需要进行分析。

数据概览：
- 行数：{n}
- 列数：{m}
- 列名和类型：{schema}
- 业务背景：{context}

请提供：
1. 数据质量报告（缺失值、异常值、重复值）
2. 描述性统计（各列分布）
3. 可视化建议（适合什么图表）
4. 初步洞察（3-5 个发现）
5. 进一步分析方向
```

### 3.2 SQL 生成

```
请根据以下需求生成 SQL 查询。

数据库：{MySQL/PostgreSQL/ClickHouse}
表结构：
{schema}

需求：{自然语言描述}

要求：
- 使用标准 SQL
- 添加注释说明逻辑
- 考虑性能优化（索引建议）
- 处理边界情况（NULL、空值）

请同时提供：
1. SQL 代码
2. 执行计划分析（如果适用）
3. 优化建议
```

## 4. 创意生成

### 4.1 产品命名

```
请为 {产品描述} 生成 20 个名称候选。

要求：
- 风格：{科技感/温暖感/专业感/趣味性}
- 长度：{2-4 个字/英文单词}
- 语言：{中文/英文/混合}
- 避免：{已有商标、负面谐音}

请按以下格式输出：

| 名称 | 含义 | 优点 | 风险 |
|------|------|------|------|
| ... | ... | ... | ... |

Top 3 推荐及理由：
1. ...
2. ...
3. ...
```

### 4.2 营销文案

```
请为 {产品/活动} 撰写营销文案。

目标受众：{描述}
渠道：{微信/微博/邮件/海报}
调性：{专业/活泼/高端/亲民}
行动号召：{具体动作}

请提供：
1. 标题（5 个候选）
2. 正文（3 个版本：简短/中等/详细）
3. 社交媒体版本（140 字内）
4. 视觉描述（配合设计的建议）
```

## 5. 通用模板

### 5.1 专家咨询

```
你是一位 {领域} 专家，拥有 {年限} 年经验。

我需要解决以下问题：
{问题描述}

背景信息：
- {背景 1}
- {背景 2}
- {约束条件}

请提供：
1. 问题分析（根因）
2. 解决方案（2-3 个选项）
3. 各方案优缺点对比
4. 推荐方案及理由
5. 实施步骤和注意事项
6. 风险规避建议
```

### 5.2 学习导师

```
我想学习 {主题}，当前水平：{零基础/入门/进阶}。

请作为我的导师：
1. 制定学习路径（分阶段，含时间 estimate）
2. 推荐学习资源（书籍/课程/项目）
3. 设计练习任务（由简到难）
4. 指出常见误区
5. 设定里程碑和检验标准

学习方式偏好：{理论型/实践型/项目驱动}
可用时间：{每周 x 小时}
```

## 💡 我的思考

1. **模板是起点不是终点**：这些模板需要根据具体场景调整，不要生搬硬套。

2. **上下文是关键**：模板中的占位符 `{...}` 需要填充充分的上下文信息，模型才能给出高质量输出。

3. **迭代优化**：第一次生成的结果往往不完美，通过多轮对话 refine 是常态。

4. **建立个人模板库**：根据你的工作场景，积累自己的 prompt 模板，效率提升明显。
