## 1. 核心区分：预训练 = 知识，后训练 = 行为

这是理解 LLM 训练最本质的一对概念：

| 维度 | 预训练 (Pre-training) | 后训练 (Post-training) |
|------|----------------------|------------------------|
| **学什么** | 世界知识、语言规律 | 行为规范、对话格式、价值观 |
| **数据** | 万亿级无标注文本（网页/书籍/代码） | 万～十万级高质量标注数据 |
| **目标函数** | 下一词预测 (Causal LM) | SFT + 偏好对齐 + RL |
| **计算量** | 极其巨大（总计算量的 ~99%） | 相对较小（~1%） |
| **时间** | 数周到数月 | 数小时到数天 |
| **产出模型** | Base Model（基座模型） | Chat/Instruct Model（对话模型） |

**直观类比**：

> - **预训练** = 一个人从 0 到 18 岁，读了整个图书馆的书。他"知道"地球绕着太阳转、水的沸点是 100°C、莎士比亚写了什么。但他不知道如何恰当跟人交流、什么时候该说什么、什么时候该闭嘴。
>
> - **后训练** = 给他上礼仪课（SFT）→ 请十个老师盯着他聊天打分（RLHF/DPO）→ 教他"遇到难题先在草稿纸上算清楚"（推理增强）。
>
> 预训练决定**能力的上限**，后训练决定**能力发挥得有多好**。

## 2. 预训练深度解析

> 详见 `pretraining.md`、`scaling-laws.md`、`training-infrastructure.md`

### 2.1 核心机制：Next Token Prediction

预训练本质上是让模型做一道巨大的"填空题"或"接龙题"。

```
输入："今天天气很 ___"
模型任务：预测"好"

输入："import numpy as np\n\ndef mean(x):\n    return ___"
模型任务：预测"sum(x) / len(x)"
```

这个任务看似简单，但要做到好，模型必须：
- 理解语法结构（中文里"很"后面接形容词）
- 掌握世界知识（"水的沸点是 100°C"）
- 学会推理（2+3=5 → 下一个是什么？）
- 掌握编程（函数体里应该写什么）

**这就是预训练的魔力**——一个简单目标逼出复杂能力。

### 2.2 数据：预训练的灵魂

预训练数据决定了模型的"知识谱系"。典型配比：

| 数据类型 | 占比 | 作用 |
|----------|------|------|
| 网页文本（Common Crawl） | 60-80% | 通用知识、语言多样性 |
| 书籍 | 10-15% | 长文本连贯性、叙事能力 |
| 代码（GitHub） | 5-15% | 推理、逻辑、结构化思维 |
| 学术论文（arXiv） | 5-10% | 专业知识、精确表达 |
| 百科（Wikipedia） | 3-5% | 事实准确性 |

**黄金法则**：数据质量 > 数据量 > 模型大小。Garbage in, garbage out 在预训练中体现得淋漓尽致。

### 2.3 Chinchilla 定律：算多少决定训多少

DeepMind 的 Chinchilla 论文（2022）给出了一条重要规律：

> 对于给定的计算预算，**模型参数量和数据量应该成比例增长**。大部分现有模型都"训少了"——参数太大、数据不够。

具体来说：**每 1 个参数，大约需要 20 个 token 的训练数据**。
- 1B 参数模型 → 约 20B tokens 训练数据
- 70B 参数模型 → 约 1.4T tokens 训练数据
- 175B 参数模型 → 约 3.5T tokens 训练数据

### 2.4 预训练的技术挑战

| 挑战 | 典型方案 |
|------|----------|
| 数据清洗 | 去重（MinHash）、质量过滤、PII 移除 |
| 分布式训练 | 数据并行 + 模型并行 + 流水线并行 |
| 显存不足 | ZeRO 优化（DeepSpeed）、梯度检查点、Flash Attention |
| 训练不稳定 | 梯度裁剪、混合精度（bf16）、学习率预热 |
| 灾难性遗忘 | 持续预训练时的数据混合策略 |

## 3. 后训练全景：三层递进

### 3.1 为什么预训练不够？

Base Model 的问题不是不知道，而是"不懂事"：

| 场景 | Base Model 的反应 | 后训练修正 |
|------|------------------|-----------|
| 用户问：写一首诗 | 继续"接龙"——可能重复 prompt 或跑偏 | SFT：学会按要求写诗 |
| 用户问：怎么制造炸弹 | 老实回答（它在互联网上读过） | RLHF：学会拒绝危险请求 |
| 用户问：1+1=? | 可能回答 2，也可能啰嗦半天 | RLHF：学会简洁准确 |
| 用户多轮对话 | 忘记前文、跑题 | SFT：学会维护上下文 |

**根本原因**：预训练的目标是"预测下一个 token"，不是"完成用户意图"。

---

### 3.2 后训练三层结构

```
Layer 1: SFT（监督微调）
  "教模型怎么对话"
  输入：(指令, 优质回复) 对
  方法：标准交叉熵损失
  效果：学会角色区分、基本安全行为、格式规范

Layer 2: 偏好对齐
  "教模型什么是好回复"
  输入：人类偏好排序 / 好-坏标签
  方法：RLHF(PPO) / DPO / ORPO / KTO / GRPO
  效果：有用性↑、安全性↑、简洁度↑、风格一致性↑

Layer 3: 推理增强（可选）
  "教模型深度思考"
  输入：带推理链的难题 + 过程奖励信号
  方法：CoT SFT / Process Reward Model / RL (GRPO)
  效果：复杂推理↑、数学↑、代码↑、自我纠错↑
```

## 4. 后训练方法族谱

### 4.1 经典派：RLHF (InstructGPT, 2022)

```
SFT → 训练奖励模型(RM) → PPO 强化学习优化
                ↑
        人类对偏好排序数据
```

**优势**：效果好，被 ChatGPT 验证过
**劣势**：实现复杂——需维护 4 个模型（Policy、Reference、Reward、Value），在线采样，超参数敏感

### 4.2 简化派：DPO (2023)

> 核心洞察：奖励模型和最优策略之间存在闭式解——不需要显式训练 RM

```
SFT + 偏好数据 → 直接优化语言模型
（一步到位！）
```

**优势**：稳定、简单、离线训练
**劣势**：偏好数据质量要求更高、无法在线学习

### 4.3 再简化：ORPO (2024)

> 核心洞察：SFT 和偏好对齐可以**在同一个阶段完成**

```
(指令, 好回复, 坏回复) → 一个损失函数搞定 SFT + 偏好对齐
```

ORPO 的损失函数 = 标准 SFT 损失 + odds ratio 惩罚项。不需要 reference model！

**优势**：两阶段合一、更省资源、不需要 reference model
**劣势**：方法较新，大规模验证较少

### 4.4 最省标签：KTO (2024)

> 核心洞察：人类对好坏回复的感知符合**前景理论**（Kahneman & Tversky）——不需要成对偏好数据

只需要**单条回复的好/坏标签**（👍 或 👎），就能训练。极大降低标注成本。

| 方法 | 需要 Reference Model | 需要成对偏好 | 训练阶段数 |
|------|---------------------|-------------|-----------|
| PPO-RLHF | ✅ | ✅ | 3 (SFT+RM+PPO) |
| DPO | ✅ | ✅ | 2 (SFT+DPO) |
| ORPO | ❌ | ✅ | 1 |
| KTO | ✅ | ❌ | 2 (SFT+KTO) |

### 4.5 RL 复兴：GRPO (DeepSeek-R1, 2025)

> 核心洞察：PPO 太复杂，RL 可以更纯粹——**不需要 Value Model（Critic）**

GRPO (Group Relative Policy Optimization) 是 DeepSeek-R1 的技术核心：

- **砍掉 Critic 网络**：不需要训练 Value function，减少一半显存
- **Group 采样**：对每个 prompt 采样多条回复，组内相对比较来计算 advantage
- **规则化奖励**：对数学/代码任务，直接用答案正确性作为 reward（无需人工标注）

```
PPO 的 reward 计算：RM_score - KL × KL_div(π, π_ref)
GRPO 的 reward 计算：group_normalized(rule_based_reward) - KL × KL_div(π, π_ref)
                       ↑ 组内归一化          ↑ 规则打分（0/1）
```

**这是推理增强的基石方法**，让模型在没有大量人工标注的情况下学会深度思考。

## 5. 推理增强：后训练的新范式

### 5.1 快思考 vs 慢思考

传统 LLM 推理是"快思考"（System 1）——看到问题，直接吐答案，没有验算机会。

推理增强训练模型学会"慢思考"（System 2）——先分析、分步推理、自我纠错、再给答案。

### 5.2 Chain-of-Thought (CoT) 到 o1

| 阶段 | 方法 | 代表 |
|------|------|------|
| **Prompt 级别** | "Let's think step by step" | 各种 prompt 技巧 |
| **数据级别** | SFT 数据中大量插入推理链 | 早期开源模型 |
| **RL 级别** | 用 RL 训练模型自主产生推理链 | OpenAI o1 (2024), DeepSeek-R1 (2025) |
| **推理时扩展** | 给模型更多"思考 token"→ 效果持续提升 | o1/o3, Claude 3.5 Sonnet thinking |

### 5.3 推理增强的核心技术要素

1. **过程奖励（Process Reward）**：不光看最终答案对不对，还对中间推理步骤打分
2. **自我纠错（Self-correction）**：训练模型在推理过程中发现并修正自己的错误
3. **Inference-time Scaling**：推理时多花计算 → 更好的结果（和训练时的 Scaling Law 对偶）
4. **规则化奖励（Rule-based Reward）**：数学题用标准答案检验，代码用执行结果检验——绕过人工标注瓶颈

### 5.4 DeepSeek-R1 的启示

DeepSeek-R1 (2025.01) 是推理增强领域的一个重要里程碑：

> **纯粹的 RL（GRPO）可以自发涌现推理能力**——不需要先做大量 CoT SFT。

R1-Zero 的实验表明：直接在基座模型上用 GRPO + 规则化奖励训练，模型会**自己学会**：
- 生成推理链（CoT）
- 自我验证
- 反思和回溯
- 在推理链中切换语言（中英混合思考）

这就像预训练里"简单目标逼出复杂能力"的翻版——后训练中，简单的 RL 奖励信号也能逼出复杂的推理行为。

## 6. 整个流程的计算经济学

| 阶段 | 占计算预算 | 数据规模 | 数据标注需求 | 主要瓶颈 |
|------|-----------|---------|-------------|---------|
| 预训练 | ~99% | TB 级 | 无需标注 | 算力、工程 |
| SFT | <0.5% | MB-GB 级 | 万条级人工标注 | 标注质量 |
| 偏好对齐 | <0.5% | MB 级 | 万条级偏好比较 | 标注一致性 |
| 推理增强 | 0.5-2% | MB 级 | 可规则自动打分 | RL 稳定性 |

> **关键洞察**：计算上，预训练占绝对大头；但**能力塑造上，后训练质量往往决定了最终产品的下限**。

## 7. 关键洞察（综合视角）

1. **预训练 = 能力的土壤，后训练 = 在上面种什么庄稼**。土壤贫瘠，再好的种子也长不好；不播种，再肥沃的土地也长不出庄稼。

2. **数据质量在两端都是王**：预训练的数据清洗决定了知识质量的上限；后训练的标注质量决定了对齐效果的上限。

3. **后训练方法在快速简化**：从 PPO（4 模型轮转）→ DPO（2 模型）→ ORPO（1 模型 + 1 阶段），门槛越来越低。2025 年的 GRPO 又给 RL 注入了新活力。

4. **推理增强是后训练的"下一章"**：o1/R1 证明了推理时计算扩展（Inference-time Scaling）是新的能力增长极，它和训练时计算扩展（Training-time Scaling）同等重要。

5. **两阶段的类比思维**：
   - 预训练 = 读万卷书（广度）
   - SFT = 学礼仪规范（格式）
   - RLHF/DPO = 被老师调教（品味）
   - 推理增强 = 学解题方法（深度）

6. **没有银弹**：不存在"只做预训练就够"或"后训练能弥补预训练缺陷"的情况。两者是乘数关系，弱项决定最终水平。
