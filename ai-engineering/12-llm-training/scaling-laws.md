# 扩展定律与计算效率

> **一句话定位**：Scaling Laws 揭示了模型性能与规模、数据、计算量之间的幂律关系——指导高效的大模型训练。

---

## 1. Scaling Laws 基础

### 1.1 什么是 Scaling Laws

Scaling Laws 描述了模型性能（通常用 loss 表示）与三个关键因素之间的幂律关系：

```
L(N, D) = E + A/N^α + B/D^β

其中：
- L: 验证集 loss
- N: 模型参数量
- D: 训练 token 数
- E: 不可约误差（irreducible error）
- A, B, α, β: 拟合参数
```

### 1.2 OpenAI Scaling Laws (2020)

**核心发现**：

| 关系 | 公式 | 说明 |
|------|------|------|
| **Loss vs 模型大小** | L ∝ N^(-0.076) | 模型越大，loss 越低 |
| **Loss vs 数据量** | L ∝ D^(-0.095) | 数据越多，loss 越低 |
| **Loss vs 计算量** | L ∝ C^(-0.050) | 计算越多，loss 越低 |

**关键洞察**：
- 模型性能随规模、数据、计算量**可预测地**提升
- 更大的模型**样本效率更高**
- 趋势跨越 **7 个数量级**

### 1.3 Chinchilla Scaling Laws (2022)

**DeepMind 的发现**：

**最优计算效率配置**：
```
对于给定的计算预算 C：
- 最优模型大小：N_opt ∝ C^0.50
- 最优数据量：D_opt ∝ C^0.50

即：模型参数和数据量应按**相同比例**扩展
```

**Chinchilla 结论**：

| 模型 | 参数量 | 训练 Tokens | 计算量 | MMLU |
|------|--------|-------------|--------|------|
| Gopher | 280B | 300B | 5.76e23 | 60.0% |
| Chinchilla | 70B | 1.4T | 5.76e23 | 67.5% |

**相同计算量，更小的模型 + 更多数据 = 更好的性能**

## 2. 计算最优训练

### 2.1 Chinchilla 最优配置

**公式**：
```
给定计算预算 C (FLOPs)：

N_opt = (C / 6)^(1/2) × (1/20)^(1/2) ≈ 0.007 × C^0.5
D_opt = (C / 6)^(1/2) × 20^(1/2) ≈ 1.83 × C^0.5

简化规则：
- 训练 token 数 ≈ 20 × 参数量
- 即：1B 参数模型需要 ~20B tokens
```

## 3. 模型大小 vs 数据量权衡

### 3.1 IsoFLOP 分析

**固定计算量，变化模型/数据比例**：

```
计算量 C = 6 × N × D (常数)

变化 N 和 D 的比例，观察性能
```

**实验结果**：

| N:D 比例 | 模型大小 | 数据量 | Loss | 结论 |
|----------|----------|--------|------|------|
| 1:1 | 中等 | 中等 | 较高 | 次优 |
| 1:10 | 较小 | 较大 | **最低** | **最优** |
| 10:1 | 较大 | 较小 | 较高 | 次优 |

### 3.2 过拟合分析

**过拟合边界**：
```
当 D < N 时（数据量 < 参数量），模型开始过拟合

Chinchilla 建议：D ≈ 20N 避免过拟合
```

**实际观察**：
- GPT-3 (175B, 300B tokens)：D/N ≈ 1.7，明显欠训练
- Chinchilla (70B, 1.4T tokens)：D/N ≈ 20，最优
- LLaMA-65B (65B, 1.4T tokens)：D/N ≈ 22，接近最优

## 4. 训练效率优化

### 4.1 训练时间估算

**公式**：
```
训练时间 = (6 × N × D) / (GPU_peak_FLOPS × GPU_num × efficiency)

示例：
- 7B 模型，1T tokens
- A100: 312 TFLOPS (FP16)
- 效率: 40%
- 64 张 A100

训练时间 = 6 × 7e9 × 1e12 / (312e12 × 64 × 0.4)
         = 4.2e22 / 7.99e15
         = 5.26e6 秒
         = 61 天
```

### 4.2 效率提升策略

| 策略 | 效果 | 代价 |
|------|------|------|
| **增加 GPU 数量** | 线性加速 | 成本增加 |
| **混合精度** | 2-3× 加速 | 精度略微损失 |
| **Flash Attention** | 2-4× 加速 | 实现复杂 |
| **梯度累积** | 等效大 batch | 训练时间不变 |
| **模型并行优化** | 减少通信 | 实现复杂 |

### 4.3 成本优化

**训练成本公式**：
```
成本 = GPU 数量 × 训练时间 × GPU 单价

优化方向：
1. 减少总计算量（Chinchilla 最优配置）
2. 提高 GPU 利用率
3. 使用更便宜的 GPU（如 T4 用于小模型）
4. 使用 spot/preemptible 实例
```

## 5. 涌现能力（Emergent Abilities）

### 5.1 什么是涌现能力

涌现能力是指模型在达到一定规模后**突然**展现出的新能力，而非线性提升。

**典型涌现能力**：

| 能力 | 涌现规模 | 说明 |
|------|----------|------|
| **上下文学习 (ICL)** | ~10B | 少量示例学习 |
| **思维链 (CoT)** | ~100B | 逐步推理 |
| **指令遵循** | ~100B | 遵循复杂指令 |
| **多语言** | ~10B | 跨语言迁移 |
| **代码生成** | ~10B | 理解和生成代码 |

### 5.2 涌现的争议

**观点 1：真正的涌现**
- 能力在特定阈值后突然出现
- 与复杂系统的相变类似

**观点 2：度量导致的涌现**
- 使用非线性度量（如准确率）导致的假象
- 如果使用连续度量（如 token 概率），能力是平滑提升的

**研究结论**：
> "Emergent abilities may be a mirage caused by the researcher’s choice of metric rather than a fundamental property of scaling LLMs." — Schaeffer et al. (2023)

## 6. 长上下文扩展

### 6.1 上下文长度挑战

**注意力复杂度**：
```
标准 Attention: O(n²) 时间和空间
- 2K context: 4M 操作
- 8K context: 64M 操作 (16×)
- 128K context: 16B 操作 (4096×)
```

### 6.2 扩展方法

| 方法 | 原理 | 代表 |
|------|------|------|
| **位置编码外推** | 训练后扩展位置编码 | ALiBi, xPos |
| **NTK-aware** | 调整 RoPE 频率 | CodeLLaMA |
| **YaRN** | 插值 + 温度缩放 | LLaMA 2 Long |
| **渐进式扩展** | 逐步增加上下文长度 | GPT-4 |

**YaRN 方法**：
```python
# 将 4K 模型扩展到 16K
scaling_factor = 4  # 16K / 4K

# 调整 RoPE 频率
freq_base = 10000 * scaling_factor ** (64 / 63)

# 温度缩放
attention_temperature = 0.1 * math.log(scaling_factor) + 1.0
```

### 6.3 长上下文训练

**数据准备**：
- 需要长文档数据（书籍、论文）
- 文档拼接：多个文档拼接成长序列
- 注意力掩码：防止跨文档注意力

**训练策略**：
```
阶段 1：标准长度预训练（4K）
阶段 2：长上下文持续预训练（32K）
阶段 3：更长上下文微调（128K+）
```

## 7. 领域适配与持续预训练

### 7.1 持续预训练（Continual Pretraining）

**场景**：
- 领域适配（医疗、法律、金融）
- 新知识注入
- 语言能力扩展

**方法**：
```python
# 在领域数据上继续预训练
# 使用较小的学习率

optimizer = AdamW(
    lr=1e-5,  # 比预训练低 10-100×
    betas=(0.9, 0.95)
)

# 混合数据：原始数据 + 领域数据
# 比例：通常 1:1 到 1:10
```

### 7.2 领域数据配比

| 场景 | 通用数据 | 领域数据 | 学习率 |
|------|----------|----------|--------|
| 医疗适配 | 50% | 50% | 1e-5 |
| 法律适配 | 30% | 70% | 5e-6 |
| 代码增强 | 50% | 50% | 1e-5 |
| 多语言扩展 | 70% | 30% | 1e-5 |

### 7.3 灾难性遗忘

**问题**：持续预训练导致通用能力下降

**缓解策略**：
1. **混合数据**：保留部分原始训练数据
2. **LoRA 适配**：只训练部分参数
3. **正则化**：EWC、经验回放
4. **逐层冻结**：从底层开始逐步解冻

## 9. 实践建议

### 9.1 模型规模选择

| 场景 | 推荐规模 | 说明 |
|------|----------|------|
| **研究/实验** | 1B-7B | 快速迭代 |
| **产品原型** | 7B-13B | 平衡性能和成本 |
| **生产部署** | 13B-70B | 根据任务复杂度 |
| **前沿研究** | 70B+ | 需要大量资源 |

### 9.2 数据量规划

```
最小数据量：D = 10 × N（避免严重过拟合）
推荐数据量：D = 20 × N（Chinchilla 最优）
充足数据量：D = 100+ × N（可能收益递减）

示例：
- 7B 模型：70B-140B tokens（推荐 1T for 最佳性能）
- 13B 模型：130B-260B tokens
- 70B 模型：700B-1.4T tokens
```

### 9.3 计算预算分配

```
总预算 = 预训练 (80%) + 微调 (15%) + 评估 (5%)

预训练预算分配：
- 模型训练：70%
- 实验和调优：20%
- 数据准备：10%
```

## 10. 总结

Scaling Laws 的核心洞察：

1. **可预测性**：模型性能随规模可预测提升
2. **最优配置**：模型和数据应等比例扩展（Chinchilla）
3. **数据关键**：高质量数据比单纯扩大模型更重要
4. **效率优先**：在固定预算下优化配置

> **关键洞察**：Scaling Laws 告诉我们"训练什么规模的模型"，但数据质量和训练策略决定了"模型能学到什么"。Scaling 是必要的，但不是充分的。
