# 后训练 (Post-Training)：从 Base Model 到 Chat Model 的完整进化

> **一句话定位**：后训练是让「满腹经纶但不会说话」的基座模型，变成「安全、有用、会聊天」的对话助手的关键环节。
>
> #status/canonical #topic/training #topic/alignment #year/2026

---

## 0. 先搞清概念：预训练与后训练的分界线

在 LLM 的世界里，整个训练流程可以清晰地切成两段：

```
┌─────────────────────────────────┐
│  预训练 (Pre-training)          │
│  万亿级无标注文本 → 学会"知道"   │
│  产出：Base Model（基座模型）    │
│  核心目标：Next Token Prediction │
└──────────────┬──────────────────┘
               │
               ▼
┌─────────────────────────────────┐
│  后训练 (Post-training)         │
│  高质量标注数据 + 人类偏好       │
│  让模型"会说人话"、"价值观对齐" │
│  产出：Chat/Instruct Model      │
│                                 │
│  ├── SFT（监督微调）            │
│  ├── RLHF/DPO（偏好对齐）       │
│  └── Reasoning Enhancement      │
└─────────────────────────────────┘
```

**一句话区分**：

> 预训练教模型「地球绕着太阳转、水的沸点是 100°C」——这是**知识**；
> 后训练教模型「问你的问题要认真回答，不知道就说不知道」——这是**行为规范**。

---

## 1. 为什么需要后训练？基座模型的「尴尬」

预训练完成的 Base Model 其实很「怪」：

| 特征 | 基座模型 | Chat 模型 |
|------|----------|-----------|
| 知道很多知识 | ✅ | ✅ |
| 听懂指令 | ❌ 更像是「造句接龙」 | ✅ |
| 拒绝有害请求 | ❌ 老实回答一切 | ✅ |
| 不知道就说不知道 | ❌ 会瞎编（hallucination） | ✅ 明确表示不确定 |
| 保持对话连贯 | ❌ 容易跑偏 | ✅ |
| 输出格式规范 | ❌ 随机 | ✅ 结构化 |

**本质原因**：预训练的目标是「预测下一个 token」，而不是「完成用户的意图」。所以基座模型看到 "写一首诗" 这个 prompt 时，它不是在「写诗」，而是在做「接在这个 prompt 后面最可能的文字是什么」的统计推测——它可能在接上另一段 prompt，也可能在重复你的话，而不是在创作。

这就是 OpenAI 在 InstructGPT 论文里说的核心洞察：**把模型变大不能自动让它更好地遵循人类意图。**

## 2. 后训练的经典三阶段流水线

这是 InstructGPT / ChatGPT 确立的标准流程，至今仍是业界主流：

```
阶段 1: 监督微调 (SFT)
  ── 用高质量「提示-回复」对教模型对话格式

阶段 2: 偏好数据收集 & 奖励模型训练 (RM)
  ── 收集人类偏好排序数据 → 训练一个"打分器"

阶段 3: 强化学习优化 (RLHF via PPO)
  ── 用奖励信号优化模型行为
```

---

## 3. 第一阶段：监督微调 (Supervised Fine-Tuning, SFT)

### 3.1 做什么

收集大量**高质量「指令→回复」对**，在这个数据集上做标准的下一词预测训练。

```
数据格式示例：
{
  "instruction": "用一句话解释相对论",
  "output": "相对论告诉我们：时间和空间不是绝对的，运动得越快时间越慢，物体越接近光速质量越大。"
}
```

### 3.2 SFT 的关键：数据质量 > 数据量

一个被反复验证的铁律：

- **几千条**高质量的人工写指令对就能让模型学会基本对话
- **几万条**高质量数据能让模型很好对话
- 低质量的合成数据再多也救不回来

**高质量 SFT 数据长什么样**：
- 多样性：覆盖写作、编程、推理、闲聊、拒绝等场景
- 一致性：同样的指令给出一致的回复风格
- 安全性：包含拒绝有害请求的示例
- 正确性：事实准确，格式规范

### 3.3 SFT 带来的能力

- ✅ 听懂指令并按要求回复
- ✅ 学会对话格式（User/Assistant 角色区分）
- ✅ 基础的安全行为（如果数据里有）
- ⚠️ 但 SFT 还不够——模型学到的是一种「表面行为」，它可能在某些场景依然输出不安全内容，或者「讨好」用户过拟合

## 4. 第二阶段：奖励模型 (Reward Model, RM)

### 4.1 核心问题

SFT 之后的模型会「对话」了，但我们如何用**数值**衡量它回复的**质量**？

"一段回复好不好"本身是主观的、多维度的（有用性、安全性、准确性、简洁度……），没法写一个简单的 loss function 来量化。

### 4.2 怎么做

RLHF 的办法是：**让人来比较，然后训练模型学会「什么叫好」**。

```
步骤：
1. 拿一堆 prompt，用 SFT 模型生成 4-9 条不同的回复
2. 让人工标注员对这些回复排序（最好的排最前）
3. 用排序数据训练一个 Reward Model（奖励模型）
   - RM 输入：(prompt, response)
   - RM 输出：一个标量分数 → 分数越高代表人类越偏好
```

**为什么用「排序」而不是「直接打分」？**

因为直接打分会引入巨大的标注者偏差——张三觉得 8 分，李四只给 5 分。而「A 比 B 更好」的二元比较远更稳定、可校准。

### 4.3 奖励模型的训练目标

RM 的训练是一个排序问题。经典做法是 Bradley-Terry 模型：

```
给定 prompt x，两个回复 y_good（好的）和 y_bad（差的）
目标：r(x, y_good) > r(x, y_bad)

Loss = -log( σ( r(x, y_good) - r(x, y_bad) ) )
```

**Llama 2 的改进**：引入了 margin 项，标注不光分好坏，还分"明显更好"还是"略微更好"，让 RM 校准得更精确。

### 4.4 RM 的规模

有趣的现象：奖励模型不需要和生成模型一样大。OpenAI 用 175B 的生成模型但只用 6B 的 reward model，效果就很好。直觉是「评价一段文字」比「生成一段文字」需要更少的参数。

## 5. 第三阶段：PPO 强化学习优化

### 5.1 强化学习视角下的对话

把对话建模成 RL 问题：

| RL 概念 | 对应的 LLM 概念 |
|---------|----------------|
| Policy（策略） | LLM 本身（给定 context，输出概率分布） |
| Action | 选择下一个 token |
| State | 当前的 prompt + 已生成的 token 序列 |
| Reward | 奖励模型给输出的分数 |

### 5.2 PPO (Proximal Policy Optimization) 的妙处

直接优化 reward 有个坑：模型会**投机取巧**（reward hacking）。

比如 RM 给「长回复」高分 → 模型开始无脑输出长文。或者生成毫无意义但 RM 识别不出的 gibberish。

**PPO 的核心约束**：不让模型偏离原始策略太远。

```
最终 reward = RM_score - λ × KL_divergence(当前策略, 参考策略)
                                      ↑
                                    KL 惩罚项
```

这个 KL 惩罚保证：
- 模型不会突然发疯，输出乱码
- 语言能力不会退化（灾难性遗忘）
- 逐步、稳定地向人类偏好方向进化

### 5.3 PPO 的工程挑战

PPO 是 RLHF 里最「工程重」的一环：

- 需要同时维护 4 个模型（Policy、Reference、Reward、Value）
- 采样和训练交替进行（on-policy）
- 超参数敏感（KL 系数、学习率、clip 范围……）
- 训练不稳定，容易发散

## 6. 简化 RLHF：DPO 的崛起

### 6.1 PPO 太复杂了 😵‍💫

PPO 的流程：
```
预训练模型 → SFT → 训练 RM → PPO 四模型轮转
```

这串流程维护成本极高，任何一个环节出错都会影响最终效果。有没有更简单的方法？

### 6.2 DPO (Direct Preference Optimization) 的核心洞察

DPO (Rafailov et al., 2023) 提出了一个优雅的数学变换：

> 奖励模型和最终策略之间存在**闭式解**——我们不需要显式训练一个 RM，可以直接用偏好数据优化语言模型本身。

**一句话解释 DPO 的妙处**：

DPO 把 RLHF 的三步（SFT → RM → PPO）**合并成一步**：直接在偏好数据上用分类损失训练 LLM，让它学会「这个回复比那个回复更好」。

```
DPO Loss = -log( σ( β × [log(π_θ(y_good|x) / π_ref(y_good|x)) 
                         - log(π_θ(y_bad|x) / π_ref(y_bad|x))] ) )
```

**对比**：

| 维度 | PPO-RLHF | DPO |
|------|----------|-----|
| 需要训练 RM | ✅ | ❌ 不需要 |
| 需要在线采样 | ✅ 需要 | ❌ 离线即可 |
| 模型数量 | 4 个 | 2 个（当前+参考） |
| 训练稳定性 | 一般 | 高 |
| 实现复杂度 | 高 | 低 |
| 效果 | 好 | 相当甚至更好 |

**DPO 的局限**：
- 偏好数据质量要求更高（垃圾进垃圾出效应更明显）
- 离线方法，没法做 online learning（让模型一边用一边学）

### 6.3 其他 RLHF 变体

| 方法 | 核心思路 | 年份 |
|------|----------|------|
| **RLAIF** (RL from AI Feedback) | 用 AI（如 GPT-4）替代人类标注偏好，大幅降本 | 2023 |
| **KTO** (Kahneman-Tversky Optimization) | 不需要成对偏好数据，只要单条回复的好/坏标签 | 2024 |
| **ORPO** (Odds Ratio Preference Optimization) | 在同一阶段同时做 SFT + DPO，省去单独的 SFT 步骤 | 2024 |
| **Rejection Sampling** | 生成多条回复，选 RM 打分最高的那条做梯度更新（Llama 2 用到） | 2022 |

### 6.4 推理时代的 RL 复兴：GRPO (Group Relative Policy Optimization)

2025 年初，DeepSeek-R1 论文引入了 GRPO，证明**纯 RL 就能在推理任务上取得惊人效果**——标记了 RL 在后训练中的复兴。

**GRPO 的核心创新**：

```
传统 PPO：
  需要 4 个模型 (Policy + Reference + Reward + Value/Critic)
  需要显式训练 Critic 网络来估计状态价值

GRPO：
  需要 3 个模型 (Policy + Reference + Reward)  ← 砍掉 Critic！
  用 Group 采样 + 组内归一化替代 Critic 的价值估计
```

**GRPO 的工作机制**：

1. **Group 采样**：对同一个 prompt，用当前策略采样 G 条不同的回复（通常 G=4~16）
2. **规则化 Reward**：数学题——答案对不对？代码题——测试用例过没过？直接用规则打分，**不需要人工标注！**
3. **组内归一化**：把 G 条回复的 reward 做 z-score 归一化，组内相对比较作为 advantage
4. **KL 约束**：仍然保持和 reference model 的 KL 散度惩罚，防止退化

```
GRPO 的 advantage 计算：

A_i = (r_i - mean(r_1..r_G)) / std(r_1..r_G)
      ↑ 组内 z-score
更新目标：最大化 A_i × logπ(a_i|s) - β × KL(π||π_ref)
                              ↑ KL 惩罚
```

**为什么 GRPO 对推理任务特别有效？**

- 数学/代码任务有**客观答案**，可以用规则打分 → 绕过了人工标注瓶颈
- Group 采样天然鼓励**探索多样性**——多条回复中总有一条推理方向是对的
- 组内比较让模型学会**区分"好的推理"和"差的推理"**，而不只是"好的最终答案"

**R1-Zero 的惊人发现**：

DeepSeek 在 R1-Zero 实验中做了件颠覆性的事——**不经 SFT，直接在 Base Model 上用 GRPO 训练**。

结果：模型**自发涌现**了推理链行为（CoT）、自我验证、反思/回溯、甚至在推理过程中切换语言思考。

这就像预训练中"简单目标（Next Token Prediction）逼出复杂能力"的翻版——在后训练中，简单的 RL 奖励信号也能逼出复杂的推理行为。

## 7. 推理增强：后训练的新边界

### 7.1 从「快思考」到「慢思考」

传统 LLM 的推理模式：
```
用户提问 → 逐 token 生成回复（auto-regressive）
```

这种方式的问题：遇到复杂推理（数学证明、逻辑谜题、多步规划），模型很容易出错——它没有「验算」的机会。

推理增强 = 训练模型学会"慢思考"（System 2）：先分析、分步推理、自我纠错、再给最终答案。

### 7.2 Chain-of-Thought (CoT) — 入门

最早是 prompting 技巧——在 prompt 里加一句「Let's think step by step」，让模型先分析再给答案。

进阶版是**训练模型内化这个习惯**：在 SFT 数据里大量加入「先思考、再回答」的范例（CoT SFT）。

但 CoT SFT 有个天花板——它只是让模型"模仿"推理格式，而不是"学会"推理。真正要让模型具备推理能力，需要 RL。

### 7.3 推理训练的激励设计：两种 Reward

推理增强不同于传统的偏好对齐，它需要更精细的 reward 设计：

| 奖励类型 | 适用场景 | 如何获得 |
|----------|---------|---------|
| **结果奖励 (Outcome Reward)** | 数学题、代码 | 答案正确 → 1，错误 → 0（规则判定） |
| **过程奖励 (Process Reward)** | 需要分步验证的推理 | 训练 PRM（Process Reward Model）对每一步打分 |

**结果奖励 vs 过程奖励的权衡**：

- 结果奖励简单粗暴、无需标注——但对于需要多步推理的问题，可能鼓励模型蒙答案
- 过程奖励更精细——但训练一个好的 PRM 本身就是很大的工程挑战
- DeepSeek-R1 的做法：以规则化的结果奖励为主，**让模型自己学会分解步骤**

### 7.4 o1 的推理范式：Large-Scale RL for Reasoning

OpenAI 2024 年发布的 o1 系列模型是一个范式转变：

> **训练模型学会「花更多时间思考」——不是吐得更快，而是吐得更深。**

**o1 的核心训练思路**（基于 System Card 及业界共识推断）：

- **强化学习驱动**：大规模 RL 训练，模型内部生成隐式思维链（hidden CoT），经过多步推理后再给最终回复
- **过程奖励模型（PRM）**：训练专门的模型对推理链的每一步打分，而不仅仅看最终答案
- **自我纠错**：模型学会在推理过程中发现错误、回溯、修正方向
- **推理时计算扩展（Inference-time Scaling）**：给定更多「思考预算」→ 效果持续提升。这是新的 Scaling Law——不光是训练多用计算，**推理时也可以多花计算换更好的效果**

**Inference-time Scaling 的两条路**：

```
方法 A：并行采样 + 投票（多数表决）
  ─ 生成 N 条独立回复 → 选最好的/投票最多的
  ─ 适合有明确对错的任务

方法 B：串行推理链延长
  ─ 模型在单条回复中花更多 token 做内部推理
  ─ 这就是 o1 的方式：让模型"想得更久"
```

### 7.5 DeepSeek-R1：纯 RL 驱动的推理涌现

DeepSeek-R1（2025.01）是推理增强领域的里程碑，它回答了核心问题：**推理能力能不能只靠 RL 训练出来？**

**R1-Zero 实验（Pure RL）**：

- 不经过任何 CoT SFT，直接在 DeepSeek-V3-Base 上用 GRPO + 规则化奖励训练
- 模型**自发涌现**：CoT 推理链、自我验证、「等等，让我再检查一下」的反思行为、甚至多语言混合思考
- 但也出现了问题：「语言混合」「可读性差」——推理过程人类难以理解

**R1 完整方案（Cold Start + RL + 冷热交替）**：

```
阶段 1：Cold Start CoT SFT（几千条高质量推理链）
  ─ 解决"可读性"问题，给模型一个好的推理格式起点

阶段 2：推理任务 RL（GRPO + 规则化奖励）
  ─ 在数学/代码/逻辑任务上大幅提升推理能力

阶段 3：Rejection Sampling + SFT
  ─ 用阶段 2 的模型生成推理数据，筛选优质样本，混合通用 SFT 数据

阶段 4：全场景 RL
  ─ 在有用性和安全性维度上再做 RL，保持 helpfullness
```

**R1 给业界的启示**：

1. RL 不是只能做"对齐"，它可以是**核心能力提升**的手段
2. 规则化奖励绕过了人工标注瓶颈，让 RL 在推理任务上大规模可扩展
3. Cold Start SFT 不是必需的——R1-Zero 证明了纯 RL 就能涌现推理——但加一点 SFT 能解决可读性问题
4. **推理能力不只来自预训练"知道更多"，而是来自后训练"学会思考"**——这是 o1/R1 对 Scaling Law 的重要补充

### 7.6 推理增强的位置

推理增强通常发生在后训练阶段——因为：

1. 预训练数据是互联网文本，缺乏高质量「分步推理→验证→纠错」的过程
2. 推理链条的生成需要 RL 来探索和优化——简单的 next-token-prediction 不会告诉模型"这个推理步骤对不对"
3. 推理和通用对话是两种不同的能力——可以在后训练中分别优化再融合

## 8. Llama 2 的后训练实践（行业参考）

Meta 在 Llama 2 的 RLHF 有几个值得关注的工程创新：

### 8.1 双奖励模型

不是一个 RM，而是**两个**：一个专注「有用性」，一个专注「安全性」。最终 reward 是两者的加权组合。

### 8.2 多轮迭代

不是训一次就完事，而是 **RLHF-V1 → V2 → ... → V5** 的渐进迭代：
- 每轮之后用新模型重新采样
- 标注员对比新旧模型输出，发现新问题
- 更新 RM 后继续优化

### 8.3 Rejection Sampling + PPO 混合

在 PPO 之外补充 rejection sampling：生成 K 条回复，只保留 RM 打分最高的那一条做训练。这在探索-利用之间取得了更好的平衡。

## 9. 后训练的常见陷阱与应对

| 陷阱 | 现象 | 应对 |
|------|------|------|
| **Reward Hacking** | 模型输出 gibberish 也能得高分 | KL 惩罚、RM 持续更新 |
| **灾难性遗忘** | RL 优化后通用能力下降 | KL 惩罚、混合预训练数据 |
| **谄媚行为** (Sycophancy) | 模型一味附和用户，丧失客观性 | 在 SFT 数据中加入「坚持正确」的范例 |
| **对齐税** (Alignment Tax) | 为了安全牺牲了太多能力 | PPO 中调低 KL 系数，更多迭代 |
| **偏好数据噪声** | 标注员意见不统一导致训练不稳定 | 增加标注一致性检查、使用 margin label |

## 11. 关键洞察

1. **预训练 = 知识，后训练 = 行为**。两者缺一不可。
2. **数据质量 > 算法花哨**。SFT 阶段的「指令-回复」对质量决定了对齐效果的上限。
3. **RLHF 的 KL 约束是防止「发疯」的定海神针**。没有它，模型会学到各种投机取巧的方式骗 reward。
4. **DPO 让对齐民主化**。不需要维护复杂的四模型 PPO 流程，小团队也能做高质量的后训练。
5. **推理增强是后训练的新疆域**。o1 证明了推理时计算扩展（Inference-time Scaling）是新的能力增长极。
6. **后训练不是一个「一次性操作」**，而是迭代循环——采样→标注→训练→再采样→再标注→再训练。

## 12. 个人理解：预训练/后训练的费曼化类比

> **预训练** = 一个小孩从 0 到 18 岁，读了整个图书馆的书。他「知道」很多，但他不知道如何恰当跟人交流、什么时候该说什么、什么时候该闭嘴。
>
> **SFT** = 给他上礼仪课——「被人问到问题，要认真回答；不知道就说不知道」。
>
> **RLHF/DPO** = 请十个老师盯着他聊天，每次他说得好就点头，说得不好就皱眉。慢慢地，他自己就内化了「什么叫好的对话」。
>
> **推理增强** = 教他「遇到难题别急着说答案，先在草稿纸上算清楚」。这跟单纯多读书是两种完全不同的能力。
