# Cognee 深度解析：给你的 AI Agent 装上"长期记忆"

> 一份面向小白的图文指南 | 2026-07

---

## 一句话讲清楚 Cognee 是什么

??? quote "一句话"
    **Cognee = 一个开源的 AI 记忆平台。你把数据丢给它，它帮你建一个"知识图谱大脑"，以后 AI 问什么都能想起来。**

    它不是什么大语言模型（它不替代 GPT/Claude），也不是简单的 RAG（检索增强生成）。它是**夹在你的数据和 AI 模型之间的那一层"记忆层"**。

## 故事：从"鱼的记忆"到"大象的记忆"

先讲个小故事，帮你理解为什么需要 Cognee。

```
┌─────────────────────────────────────────────────────────────┐
│ 场景 1：没有记忆的 AI（就是你现在用的 ChatGPT 默认状态）        │

│  你：昨天我们聊的那个项目进度怎么样了？                        │
│  AI：抱歉，我不记得之前的对话了。你能再说一遍吗？               │
│                                                             │
│  问题：每次对话都是独立的，对话结束，记忆清零。                  │
│        像鱼：7 秒记忆，转头就忘。                               │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 场景 2：有 Cognee 的 AI                                       │
│                                                             │
│  你：昨天我们聊的那个项目进度怎么样了？                        │
│  AI：您昨天说后端 API 已经完成 80%，前端还在等设计稿。           │
│      需要我现在帮您跟进前端设计吗？                             │
│                                                             │
│  因为有 Cognee 帮忙记住：                                     │
│  • 昨天的对话内容 → 存进"知识图谱"                             │
│  • "API"和"前端"的关系 → 也记下来了                            │
│  • "项目进度"这个概念 → 关联到这些信息                         │
│                                                             │
│  像大象：记性超好，还能联想。                                  │
└─────────────────────────────────────────────────────────────┘
```

## Cognee 的核心四步：Remember → Improve → Recall → Forget

Cognee v1.0 的 API 设计得非常简洁，只有四个操作：

```
                      ┌──────────────┐
                      │              │
        你把数据丢进来 │  .remember() │  存入记忆
        ────────────▶ │              │
                      └──────┬───────┘
                             │
                             ▼
                      ┌──────────────┐
                      │              │
          让它自己优化 │  .improve()  │  记忆升级
        ────────────▶ │              │
                      └──────┬───────┘
                             │
                             ▼
                      ┌──────────────┐
                      │              │
         你用自然语言问│  .recall()   │  检索回答
        ────────────▶ │              │
                      └──────┬───────┘
                             │
                             ▼
                      ┌──────────────┐
                      │              │
             不需要就删│  .forget()   │  删除记忆
        ────────────▶ │              │
                      └──────────────┘
```

### 1. `remember()` — 记住

把文字、文件（PDF/Word/图片/音频）、URL 都丢进去，Cognee 帮你消化吸收。

```python
import cognee

# 最简单的用法 —— 一句话就记下来
await cognee.remember("爱因斯坦出生在德国乌尔姆。")

# 也可以带会话 ID，用于临时对话记忆
await cognee.remember(
    "用户喜欢详细的解释。",
    session_id="chat_1"
)
```

### 2. `improve()` — 自我优化

让 Cognee 对自己已有的知识图谱做一轮"复习"——提取更深层的关联、加反馈权重、把会话记忆桥接到永久记忆。

```python
# 对已有知识库做一轮增强
await cognee.improve(dataset="my_knowledge")

# 把某个会话的短期记忆"转正"成长期记忆
await cognee.improve(session_ids=["chat_1"], dataset="my_knowledge")
```

### 3. `recall()` — 回忆

用自然语言问问题，Cognee 自动选择最佳检索策略。

```python
results = await cognee.recall("爱因斯坦出生在哪里？")
for r in results:
    print(r)
```

### 4. `forget()` — 忘记

不想记住了？删掉就好。

```python
await cognee.forget(dataset="my_knowledge")
```

### 三层存储架构（最关键的设计）

Cognee 为什么强大？因为它**同时用三种数据库**，每种干不一样的事。

```
┌──────────────────────────────────────────────────────────────┐
│                    Cognee 三层存储                            │
│                                                              │
│  ┌─────────────────┐   ┌─────────────────┐   ┌────────────┐ │
│  │   关系数据库     │   │   向量数据库     │   │  图数据库   │ │
│  │   (PostgreSQL)   │   │   (PGVector/    │   │ (Neo4j/    │ │
│  │                 │   │    LanceDB/...) │   │  PG Graph) │ │
│  ├─────────────────┤   ├─────────────────┤   ├────────────┤ │
│  │                 │   │                 │   │            │ │
│  │ 存什么：        │   │ 存什么：        │   │ 存什么：   │ │
│  │ • 文件来源      │   │ • 文本的        │   │ • 实体节点  │ │
│  │ • 谁创建的      │   │   数字指纹      │   │ • 实体关系  │ │
│  │ • 什么时候      │   │ • 概念向量      │   │ • 知识结构  │ │
│  │ • 属于哪个      │   │                 │   │            │ │
│  │   数据集        │   │ 能做什么：      │   │ 能做什么：  │ │
│  │                 │   │ "这段话在说     │   │ "A和B是     │ │
│  │ 能做什么：      │   │  什么？"       │   │  什么关系？"│ │
│  │ "这个数据       │   │  用意思搜      │   │  用关系搜   │ │
│  │  从哪来的？"   │   │                 │   │            │ │
│  └─────────────────┘   └─────────────────┘   └────────────┘ │
│                                                              │
│  打个比方：                                                   │
│  关系数据库 = 图书馆的借阅登记本（谁借了哪本书）                │
│  向量数据库 = 谷歌搜索（输入大概意思，找到相关文章）            │
│  图数据库   = 维基百科的超链接（从 A 连到 B，B 连到 C...）    │
└──────────────────────────────────────────────────────────────┘
```

**为什么一个不够？**

| 需求 | 关系数据库 | 向量数据库 | 图数据库 |
|------|:----------:|:----------:|:--------:|
| "这个文档是谁创建的？" | ✅ 擅长 | ❌ | ❌ |
| "这段话大概在讲什么？" | ❌ | ✅ 擅长 | ❌ |
| "这个概念和哪些概念相关？" | ❌ | ❌ | ✅ 擅长 |
| "综合以上三种查询" | — | — | — |

Cognee 把三者捏在一起，所以你问一个问题，它能同时从这个三个维度找答案。

### 知识图谱是怎么建出来的？

这是 Cognee 最核心的"魔法"。来看看 `remember()` 底下到底发生了什么：

```
输入："爱因斯坦 1879 年出生于德国乌尔姆，1905 年发表了狭义相对论。"

            │
            ▼
    ┌───────────────┐
    │ 1. 文本分块    │ 切成合适大小的片段，方便处理
    └───────┬───────┘
            │  "爱因斯坦 1879 年出生于德国乌尔姆..."
            ▼
    ┌───────────────┐
    │ 2. 实体提取    │ LLM 找出"谁"、"哪里"、"什么"
    └───────┬───────┘
            │  实体：爱因斯坦、德国、乌尔姆、狭义相对论
            ▼
    ┌───────────────┐
    │ 3. 关系抽取    │ LLM 找出它们之间怎么连的
    └───────┬───────┘
            │  关系：出生在、位于、发表了
            ▼
    ┌───────────────┐
    │ 4. 构建图谱    │ 变成图数据库里的节点和边
    └───────┬───────┘
            │
            ▼

    生成的图（简化版）：

                   ┌──────────┐
                   │  乌尔姆   │
                   └─────┬────┘
                         │ 位于
                         ▼
                   ┌──────────┐
                   │  德国     │
                   └──────────┘
                         ▲
                         │ 出生在
                   ┌─────┴────┐
                   │ 爱因斯坦  │
                   └─────┬────┘
                         │ 发表了
                         ▼
                   ┌───────────┐
                   │ 狭义相对论 │
                   └───────────┘

    再加上向量（数字指纹）：
    "爱因斯坦" → [0.23, -0.45, 0.78, ...]（768 个数字的向量）
    "相对论"   → [0.19, -0.41, 0.82, ...]（768 个数字的向量）

    以后你搜索"现代物理学的奠基人是谁？"
    → 向量搜索找到"爱因斯坦"（概念上相似）
    → 图搜索沿着关系找到"狭义相对论"、"量子理论"...
    → 返回完整答案！
```

### 两种记忆模式：短期 vs 长期

Cognee 把记忆分成两层，像一个聪明的秘书：

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  会话记忆（Session Memory）         永久记忆（Permanent） │
│  ┌─────────────────────┐          ┌──────────────────┐  │
│  │ 快                    速度      慢（要建图谱）       │  │
│  │ 临时说话内容           内容      整理后的知识        │  │
│  │ 文件缓存               存储      知识图谱            │  │
│  │ 当前对话               生命周期   跨对话永久          │  │
│  │                       │          │                  │  │
│  │ remember(session_id)  │   improve│  ← 桥接          │  │
│  │ ──────────────────────┼─────────▶│                  │  │
│  │                       │  （可以把会话记忆"转正"）    │  │
│  └─────────────────────┘          └──────────────────┘  │
│                                                         │
│  类比：                                                  │
│  会话记忆 = 便利贴（随手记，方便，但容易丢）               │
│  永久记忆 = 文件夹归档（慢一点，但永远在）                 │
│  improve  = 把便利贴上的重要内容抄到归档文件夹里           │
└─────────────────────────────────────────────────────────┘
```

## 检索（Recall）是怎么工作的？

当你问一个问题，Cognee 不是随便搜的。它有一个智能路由器：

```
用户问题："爱因斯坦的相对论是在哪一年提出的？"

         │
         ▼
  ┌──────────────┐
  │ 智能路由      │  分析问题类型
  │ Auto-Router   │
  └──────┬───────┘
         │
    ┌────┴────┬─────────┬──────────┬──────────┐
    ▼         ▼         ▼          ▼          ▼
  概括型    关系型     时间型     代码型     精确匹配
  "总结"    "A和B     "什么时候"  "规则"     "原话"
  是什么    的关系"
    │         │         │          │          │
    ▼         ▼         ▼          ▼          ▼
  摘要      图扩展     时间线    代码规则    词法搜索
  检索      检索       检索      检索        检索
    │         │         │          │          │
    └────┴────┴─────────┴──────────┴──────────┘
                       │
                       ▼
              ┌────────────────┐
              │ 混合结果        │
              │ 向量 + 图       │
              └────────┬───────┘
                       │
                       ▼
              ┌────────────────┐
              │ LLM 生成答案    │
              │ 带上找到的上下文│
              └────────────────┘
```

**核心点：Cognee 默认不是简单做"关键词匹配"，而是先分析你的问题意图，再选最合适的检索方式。**

## 反馈学习：越用越聪明

Cognee 有一个独特的设计——**反馈权重系统**：

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  用户问："爱因斯坦出生在哪？"                              │
│       │                                                 │
│       ▼                                                 │
│  Cognee 从图谱中找到答案 → "乌尔姆，德国"                  │
│       │                                                 │
│       ▼                                                 │
│  用户反馈：👍 "很准确！"                                  │
│       │                                                 │
│       ▼                                                 │
│  improve() 更新权重：                                     │
│  ┌─────────────────────────────┐                        │
│  │ 节点"爱因斯坦" feedback + 0.1 │                       │
│  │ 边"出生在"     feedback + 0.1 │                       │
│  │ 节点"乌尔姆"   feedback + 0.1 │                       │
│  └─────────────────────────────┘                        │
│       │                                                 │
│       ▼                                                 │
│  下次问到相关问题，正确答案的权重更高，排名更靠前           │
│                                                         │
│  用户反馈：👎 "不对"                                      │
│       │                                                 │
│       ▼                                                 │
│  对应节点/边的权重降低 → 以后不容易被检索出来              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

这就意味着：**Cognee 的记忆质量会随着使用越来越好，不需要重新训练模型。**

### Cognee 的一个巧妙设计：全跑在 PostgreSQL 上

通常情况下，你要同时维护四个存储：
- Neo4j（图） + 向量数据库 + Redis（缓存） + PostgreSQL（元数据）

Cognee 1.0 可以**全部跑在一个 PostgreSQL 上**：

| 记忆层 | 传统方案 | Cognee on Postgres |
|--------|----------|-------------------|
| 关系 | Neo4j | Postgres 图后端 |
| 向量 | 独立向量数据库 | pgvector 扩展 |
| 缓存 | Redis | SQL 会话缓存 |
| 元数据 | 关系数据库 | 还是同一个 Postgres |

> 这对小团队和个人开发者非常友好——一个 PostgreSQL 实例搞定一切。

## 真实使用场景

### 场景 1：客服 Agent 变聪明

```
传统客服：
  用户：我的发票有问题，还没解决。
  客服：您好，请问您的订单号是？问题详情是？（每次都是全新开始）

有 Cognee 的客服：
  用户：我的发票有问题，还没解决。
  客服：我查到您上月有两个类似账单问题已解决。
        原因是支付系统和发票系统之间的同步延迟。
        您的账户已经应用过修复方案，我帮您确认一下。
  
  Cognee 做了什么：
  ① 记住用户之前的对话和问题（会话记忆）
  ② 关联到历史案例（知识图谱）
  ③ 找到成功解决方案（向量+图谱检索）
  ④ 更新记忆（避免重复犯错）
```

### 场景 2：专家知识传承（SQL 助手）

```
新手分析师：这个数据集怎么算客户留存率？

Cognee 做了什么：
  ① 提取资深分析师写过的 SQL 模式
  ② 匹配当前数据表结构和之前见过的结构
  ③ 找到类似任务的成功实现
  ④ 适配专家逻辑到当前场景

结果：新手能产出接近专家水平的结果
```

**一句话区分：**

- **RAG** = 拿文档去匹配问题 → "这段话讲了什么？"
- **Cognee** = 拿文档建一个会生长的知识脑图 → "这些事情之间有什么关系？为什么是这样？"

import cognee
import asyncio

async def main():
    # 记住一些信息

## 关键术语速查表

| 术语 | 白话解释 |
|------|---------|
| **DataPoint** | Cognee 里的最小知识单元，类似"一个知识点" |
| **Task** | 一个处理步骤，比如"提取实体"、"生成摘要" |
| **Pipeline** | 把多个 Task 串起来的流水线 |
| **Embedding** | 把文字变成一串数字（向量），让计算机能"理解"意思 |
| **知识图谱** | 用节点（实体）和边（关系）画出来的知识网络 |
| **Ontology** | 一个领域的标准知识分类体系，比如医学里"感冒"属于"呼吸系统疾病" |
| **Chunk** | 把长文档切成的小段，方便处理 |
| **Session ID** | 会话编号，区分不同对话 |

## 总结：Cognee 解决了什么问题？

```
                    没有 Cognee                   有 Cognee

单个对话             聊完就没                      能记住这次聊了什么
跨对话               完全无关联                    能找出历史对话的关联
文档知识             每次重新喂给 AI               一次性存入，永久可用
知识关联             靠你自己手动整理              自动发现实体间的关系
记忆质量             不会变                        反馈越多越准确
部署                 依赖一堆中间件                 一个 PG 就能跑
```

**核心价值 = 给 AI 装上能自我进化的长期记忆。**

Cognee 不是你聊天的那个 AI，但有了它，你聊天的那个 AI 再也不会"失忆"了。
