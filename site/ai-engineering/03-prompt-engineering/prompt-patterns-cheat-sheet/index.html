    Prompt 模式速查表¶

    常用 Prompt 设计模式与技巧的快速参考，覆盖从基础到高级的各种场景。

    1. 基础模式¶

    1.1 Zero-Shot（零样本）¶

    直接给出指令，不提供示例。

    将以下中文翻译成英文：
"人工智能正在改变我们的生活。"

    适用：简单、明确的任务

    1.2 Few-Shot（少样本）¶

    提供 2-3 个示例，让模型学习模式。

    将中文翻译成英文：
中文：你好世界
英文：Hello world

中文：今天天气很好
英文：The weather is nice today

中文：人工智能正在改变我们的生活
英文：

    适用：需要特定格式、风格或模式的任务

    技巧： - 示例要覆盖边缘情况 - 输入输出格式保持一致 - 示例质量比数量更重要

    2. 推理增强模式¶

    2.1 Chain-of-Thought (CoT) 思维链¶

    引导模型逐步推理，显著提升复杂任务准确率。

    问题：一个农场有鸡和兔，共 35 个头，94 只脚。鸡和兔各有多少只？

请逐步思考：
1. 设鸡有 x 只，兔有 y 只
2. 根据头的数量：x + y = 35
3. 根据脚的数量：2x + 4y = 94
4. ...

    适用：数学、逻辑推理、多步骤问题

    变体： - Zero-Shot CoT：在问题后加"Let's think step by step" - Self-Consistency：多次采样，选择最一致的答案

    2.2 ReAct（Reasoning + Acting）¶

    推理与行动交替，适合需要工具调用的场景。

    你需要查询今天的天气，然后给用户穿衣建议。

思考 1：我需要知道用户所在城市和今天天气
行动 1：调用 weather_api(city="北京")
观察 1：今天北京晴天，25°C

思考 2：晴天 25°C 适合穿短袖
行动 2：输出穿衣建议

    适用：Agent、工具调用、多步骤任务

    3. 结构化输出模式¶

    3.1 JSON 模式¶

    强制模型输出符合 JSON Schema 的结构化数据。

    分析以下用户评论，输出 JSON 格式：
{
  "sentiment": "positive|negative|neutral",
  "key_points": ["要点1", "要点2"],
  "suggestions": ["建议1", "建议2"]
}

评论："这个产品很好用，但是价格有点贵。希望有更多颜色选择。"

    技巧： - 明确定义字段类型和枚举值 - 提供完整的 Schema 示例 - 使用 OpenAI Structured Outputs 确保格式正确

    3.2 XML/标签模式¶

    用 XML 标签组织复杂输出。

    请分析以下代码，用 XML 格式输出：
<code>
  <summary>代码功能摘要</summary>
  <issues>
    <issue severity="high|medium|low">问题描述</issue>
  </issues>
  <suggestions>
    <suggestion>改进建议</suggestion>
  </suggestions>
</code>

    4. 角色与上下文模式¶

    4.1 角色扮演¶

    给模型设定特定角色，提升输出质量。

    你是一位资深 Python 工程师，有 10 年开发经验。
请审查以下代码，关注：
1. 性能优化
2. 代码可读性
3. 潜在 bug

代码：...

    技巧： - 角色要具体（"资深后端工程师"比"专家"好） - 说明角色的经验和关注点 - 可以设定对话风格（严谨、幽默、简洁）

    4.2 系统提示词模板¶

    你是 {角色}，擅长 {领域}。

你的工作原则：
1. {原则1}
2. {原则2}
3. {原则3}

输出格式：
- 使用 {格式}
- 包含 {必要元素}
- 避免 {禁止内容}

当前任务：{任务描述}

    5. 高级技巧¶

    5.1 自我一致性检查¶

    让模型检查自己的输出。

    请回答以下问题，然后检查你的答案是否合理：

问题：...

答案：...

检查：
1. 答案是否完整？
2. 是否有逻辑错误？
3. 是否有遗漏的情况？

    5.2 多视角分析¶

    让模型从不同角度分析问题。

    请从以下三个角度分析这个方案：

[技术架构师视角]
- 关注：可扩展性、性能、技术债务

[产品经理视角]
- 关注：用户需求、商业价值、交付周期

[安全工程师视角]
- 关注：数据安全、合规、风险

    5.3 迭代优化¶

    通过多轮对话逐步优化输出。

    Round 1：生成初稿
Round 2：指出问题并要求改进
Round 3：进一步细化特定部分
...

    6. 常见 Bad Case 与修复¶

    问题 原因 修复方法
    输出太长 指令不明确 明确字数限制或格式要求
    格式错误 Schema 不清晰 提供完整示例，使用 Structured Outputs
    幻觉 知识不足 提供上下文，使用 RAG
    偏离主题 指令模糊 使用系统提示词固定角色和范围
    过度安全 模型保守 调整 temperature，明确说明场景

    💡 我的思考¶

    1. Prompt 工程是"沟通艺术"：好的 Prompt 不是堆砌技巧，而是清晰表达需求。先想清楚自己要什么，再选择合适模式。

    2. 少即是多：简单的 Few-Shot 往往比复杂的 CoT 更有效。不要过度工程化 Prompt。

    3. 版本管理很重要：Prompt 的微小改动可能导致输出质量大幅变化。建议用 Git 管理 Prompt，记录变更和效果。

    4. 结构化输出是生产环境必备：JSON/XML 模式不仅方便解析，还能强制模型思考输出结构，减少遗漏。

    5. Temperature 是被低估的参数：大多数场景用 0.1-0.3 就够了。高 Temperature 适合创意任务，低 Temperature 适合确定性任务。
